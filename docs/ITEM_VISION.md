# 独立物品识别模型

0.8.16当前选型为`models/items22/model/items22-selected.pt`，包含22类；旧19类及其他训练检查点一并归档。文件哈希和评估报告见`models/manifest.json`与`models/README.md`。当前OCR文字门槛为75%，真实单笔交易另经专用执行器处理；下文保留最初19类、本地试验阶段的设计记录，不能替代当前运行说明。

新增19类物品模型，和原有14类UI模型并行。原始UI权重及类别顺序不变；物品输出位于 `VisionResult.Items`，不会混入 `Regions`。可选配置 `ItemYoloModel`、`ItemYoloSha256`、`ItemClasses`、`ItemNavigationClasses`，未配置时兼容原流程。工作进程校验两模型哈希及类别表。调试窗用独立颜色显示物品框。

`tools/ItemVision/prepare.py` 保存来源哈希、人工标注、父图关系和裁剪图。按原始截图划分训练/验证；合成与裁剪的后代不跨集合。少量同次会话截图仅构成开发验证集，不代表独立游戏会话。盒装弹药按弹种分类，单颗弹头仅归为通用类别，弹种须由OCR确认。最后的仓库图包含DVC12、M995、7.62×39 AP和.338 AP，属于训练图，复测不能算独立验证。

`train.py` 从旧UI权重迁移，单独保存新模型；`refine.py` 保留首轮权重和评估，再解冻全模型微调。训练数据和产物路径在脚本中明确限定于本次工作目录。`evaluate.py` 使用与运行时相同的 `item_vision.predict_items`：全图和商品/仓库ROI真实推理，框还原为原图归一化坐标，按类别NMS；记录每次推理原始结果，置信度不作提升。

开发验证按IoU≥0.5统计多阈值TP/FP/FN。无独立验证样本的类别明确标为NoHoldout。训练种子复测与仓库训练图复测单列，不能充当验证集成绩。0.95阈值下有样本、全检出且无误报的类别才进入本地试验列表；小样本通过并不等于正式验收。

本地试验中的商品定位必须同时满足原UI商品卡框、物品框、同帧准确全名及上下文。物品和UI置信度均至少0.95；名称OCR至少0.90，且唯一关联同一商品卡。点击仍取原UI商品卡中心。冲突或多个候选时拒绝。MK II统一全名为“MK II破片手榴弹”，不把MKI模糊替换成MKII。

现有本进程测试窗口、前台校验、输入时效和暂停保护不变。MAX只识别，不因此开放任何购买、补齐、兑换、出售操作。类别或商品定位成功不能证明未提供的手雷兑换详情已通过。费用继续读取兑换界面的合计价格与产品市场价；材料列表不完整不阻塞默认总价采集。
